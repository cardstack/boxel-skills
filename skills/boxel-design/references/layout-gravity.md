# Layout gravity wells

Part of [`boxel-design`](../SKILL.md). Links are relative to this file.

Defaults a generator drifts into when nobody decided the layout, most of them on app screens
(desks, lists, forms, settings) rather than front pages; for front pages see the clichés in
[`critical-rules.md`](critical-rules.md) and the first-screen rule in
[`layout-vocabulary.md`](layout-vocabulary.md). A reference to check a finished layout against, not
a step: name any well the layout still contains, and keep one only when you can say why. A well the
user asked for stays: this check is for defaults nobody chose, so don't flag it again.

| Well | Looks like | Why it fails | Resist with |
|---|---|---|---|
| Header as hero | Name left, badge right, then content | The most important object sits below the line of attention | Put the key figure or featured item in the top band; identity becomes the caption (the first screen answers the first question) |
| Equal-card grid | Three or four identical boxes in a row | Says every fact matters equally, so none does | Weight by importance: one item leads, the rest follow — see *bento* and *unequal split* in [`layout-vocabulary.md`](layout-vocabulary.md) |
| Identical tiles | N same-size items regardless of rank or state | Hides the story the data tells — tier, urgency, rarity | Group with headings, vary span by rank, promote the first row; for images, *masonry* in [`layout-vocabulary.md`](layout-vocabulary.md) |
| Form above content | Input panel first, results under it | The result is the point; the form is a tool | Make the input the screen for an operator, or move it to a rail |
| Dropdown as primary control | Full-width select that changes everything | Reads as a form field, not a decision | A chip, a segmented control, or a rail with the current choice visible |
| Table as default list | Every collection is a table | Tables suit evidence, not browsing or choosing | Shelf, rail, magazine or grouped rows, by the job (named moves: [`layout-vocabulary.md`](layout-vocabulary.md)) |
| Settings panel for a ritual | A scheduled action as a labelled box with a button | No sense of when | Attach the action to a date on a strip or calendar |
| Sidebar by habit | Left nav because apps have one | Costs 20% of width for four destinations | Tabs in the top bar until there are more than seven |
| Centre everything | Every block and heading centred | No reading order | Left-align text; centre only the one spotlight object |
| Disabled-button wall | Many greyed buttons with the same reason | A wall of failure | One contextual prompt; hide the action until it can work |
| Empty state as apology | "No items yet." | Nothing to do next | Name the first action and what will appear |
| Same padding everywhere | One spacing value for hero, cards and rows | No rhythm, no grouping | Bigger gaps between groups than inside them |
| Uniform radius and shadow | Every box rounded and lifted alike | Everything floats, nothing is grounded | Radius and elevation by role — containers flat, actionable items lifted — see *layered surface* in [`layout-vocabulary.md`](layout-vocabulary.md) |
| Stock photo tile | Image, title, price, button, repeated | E-commerce default, forgettable | Choose the media treatment deliberately: cut-out, tinted, framed, or none |
