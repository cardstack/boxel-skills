# Screen types and layout directions

Three directions per screen type. Pick one and adapt the boxes to the unit's real blocks; keep the
ratios and the dominant object. Every direction states: dominant object and share · reading order ·
primary action position · above the fold at 1200×700 · how it stacks at 400.

Legend: `█` dominant · `▓` secondary · `░` tertiary · `[A]` primary action.

## desk / dashboard
Landed on many times a day. One thing to notice, one thing to do.

**A · Spotlight** — when one number carries the screen
```
┌──────────────────────────────────────────────┐
│ ████████████████████████  ▓▓▓▓▓▓▓▓▓▓▓▓▓ [A] │ 60/40
│ ███ the figure + its gap █  ▓ who / when ▓▓ │
├──────────────────────────────────────────────┤
│ ░░░░░░░░░░░░ list / ledger ░░░░░░░░░░░░░░░░ │ full width
└──────────────────────────────────────────────┘
```
Dominant: the figure, 60% of the top band. Reading: Z. Action top right. Above fold: figure, gap,
first four rows. At 400: stack, figure first.

**B · Ranked rows** — when the grouping is the story
```
┌──────────────────────────────────────────────┐
│ ▓ filters ▓                              [A] │
│ ████ tier / group heading ████████████████   │
│  ▓ item  ▓ item  ▓ item                      │
│ ████ next group ██████████████████████████   │
│  ▓ item  ░ item                              │
└──────────────────────────────────────────────┘
```
Dominant: the grouping; the top group's tiles run larger. Reading: F. Action top right. Above fold:
first two groups. At 400: one column, headings sticky.

**C · Timeline** — when *when* is the question
```
┌──────────────────────────────────────────────┐
│ ░ Jan ─●──●────●───▓▓ now ▓▓──────●── Dec ░ │ the period is the object
│        ▓ chips: state · next · owner         │
├──────────────────────────────────────────────┤
│ ░░░░ what falls in the selected span ░░░░░░ │
└──────────────────────────────────────────────┘
```
Dominant: the strip. Reading: left to right, then down. Action: on the strip. At 400: strip scrolls
horizontally, detail below.

## record / detail
One object, examined. The domain question must be answered above the fold.

**A · Hero and rail** — media or a headline figure leads, meta in a right rail, detail below.
60/40 top band, full-width detail. Action in the rail.

**B · Sectioned with nav** — a left or sticky section nav, one column of sections. For records with
5+ distinct areas. Action pinned in the header.

**C · Editorial** — eyebrow, large headline, one wide media block, then two columns of detail.
For records people read rather than scan.

## collection / browse
Choosing among many. Never an equal grid of identical tiles.

**A · Shelf** — horizontal rows by category, each row scrolling. Featured item double width.
**B · Magazine** — one large lead item, then a grid at half scale. Reading: spotlight then F.
**C · Table** — only when the job is comparing evidence field by field. Sort and filter visible.

## check-in / operator
One input, fast, repeated. The result is the screen.

**A · Input is the screen** — a large single field centred in the top third, result below it in place.
**B · Input in a rail** — field and history in a left rail, result occupying the rest.
**C · Queue** — a list of pending items, the current one expanded in place.

## form / create
**A · Sectioned** — fields grouped into task sections with a section rail. Default for 8+ fields.
**B · Stepped** — one section per step with visible progress. When order is genuinely required.
**C · Inline** — a single short block. Only for 3–5 fields.

## empty / first run
Not a screen type of its own, but every screen needs one: name the first action, show where the
result will appear, and put the action inside that shape.
