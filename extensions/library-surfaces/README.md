# library-surfaces — Use the surfaces UI framework

**What this gives you:** Layout / Pane / Form / Grid / Cell / Run / Lift primitives + focus-tree keyboard navigation + pluggable CSS themes — all from a realm-bundled library that lives next to your cards. **Plus a full table engine** (TanStack table-core inlined into `surfaces/grid/`) and a **spatial scene runtime** (ember-lume POC primitives inlined into `surfaces/scene/`).

**When to use:** You're building a card that needs structured editing (heterogeneous labeled fields), homogeneous data lists, multi-pane layouts, surface-context-aware field views, **data tables** (sortable / filterable / paginated / grouped — via TanStack), or **spatial canvases with camera-drag and momentum-scroll** (via the scene runtime). Effectively: anything more sophisticated than the default isolated/edit template.

**The insight:** Surfaces gives Boxel a real UI vocabulary. `form` is for **named, distinct slots** (Tab navigates by label). `grid` is for **indexed, repeated items** (Arrow navigates by position). `cell` is the editable leaf; `run` is the display leaf. A field defined once with `<Cell>` (for atom/edit) + `<Run>` (for embedded) renders correctly inside either surface — no per-context fork.

**Where the library lives:** Canonical bundle at the **`common-libs`** realm (under `https://realms-staging.stack.cards/ctse/common-libs/`):

```
common-libs/
└── surfaces/
    ├── index.js              ← imported from here via absolute URL
    ├── components.js, modifiers.js
    ├── manifest.json
    ├── chunks/               ← lazy chunks
    ├── layout/               ← Layout / Pane / Form / Grid / Cell / Run / Lift
    ├── grid/                 ← table engine — re-exports @tanstack/table-core
    ├── scene/                ← spatial scene runtime — ember-lume POC primitives
    ├── canvas/               ← canvas surface (XYFlow-style, native to surfaces)
    ├── themes/               ← drop-in CSS themes (boxel, figma, linear, notion, spotify)
    └── styles/
```

Cards in any **other** realm import via the absolute URL:

```ts
import { Cell, Run, /* … */ } from 'https://realms-staging.stack.cards/ctse/common-libs/surfaces/index.js';
```

Cards **inside common-libs itself** use the relative path `'./surfaces/index.js'`.

**Recipe shape:**

1. Confirm the `surfaces/` bundle exists at `https://realms-staging.stack.cards/ctse/common-libs/surfaces/`. If not, **either** rebuild from the surfaces source repo (`npm run realm` targeting common-libs) **or** upload the snapshot at `.claude/extension-libs/surfaces/` into the target realm — see [`.claude/extension-libs/README.md`](../../extension-libs/README.md) for the three upload methods (`boxel realm push` recommended for the 7.6 MB tree).
2. Import the primitives you need from the absolute URL above.
3. Wrap your card's outer container with `{{surfaceRoot focusTree=... id='layout:card' surface='layout'}}`.
4. Compose using surface kinds — `<Layout>`, `<Pane>`, `<Form>`, `<Grid>`, `<Cell>`, `<Run>`.
5. Optionally apply a theme by linking one of `https://realms-staging.stack.cards/ctse/common-libs/surfaces/themes/{boxel,figma,linear,notion,spotify}.css`.

**Gotchas:**
- The bundle is regenerated by `scripts/build-realm-bundle.mjs`. Don't edit `surfaces/index.js` by hand.
- `Cell` and `Run` adapt their chrome to the surrounding surface context — wrap them in `<Form>` for form chrome, `<Grid>` for table chrome.
- Themes use **Boxel's existing tokens** (`--background`, `--muted`, `--border`, `--radius`) — don't invent a parallel `--surface-*` namespace.
