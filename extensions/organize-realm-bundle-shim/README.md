# organize-realm-bundle-shim — Realm-bundled library with a generated re-export shim

**What this gives you:** A way to ship a substantial library *inside* a realm — surfaces, bxl, ember-flow, any local helper kit — that cards import via a stable relative path while the actual code lives in a bundled folder. Effectively: Boxel's de-facto package manager, because realms don't resolve npm.

**When to use:** You have a non-trivial body of code (a library, an SDK, a CSS-token system, a parsing engine) that multiple cards need. You don't want each card to import 20 individual files, you can't publish to npm (cards don't `npm install`), and you want a single regenerable artifact.

**The insight:** Two pieces:
1. A generated **shim file** at the realm root (`<lib>.ts`) that's a one-line re-export of the bundle index.
2. A bundled **library directory** (`<lib>/`) containing `index.ts` + `<lib>-chunks/*` for lazy-loaded sub-libraries.

Cards import `from '../<lib>'` and the realm server resolves to the shim. The shim collapses to the index. The chunks are streamed independently by the realm prerenderer. **The shim is the "package name" — the bundle is the "package contents."**

**Recipe shape:**

```
<realm>/
├── <lib>.ts                       ← shim (generated)
└── <lib>/
    ├── index.ts                   ← bundle entry
    ├── manifest.json              ← what's in the bundle (versions etc.)
    └── <lib>-chunks/              ← lazy chunks
        ├── chunk-XYZ.ts
        ├── feature-1.ts
        └── feature-2.ts
```

```ts
// <realm>/<lib>.ts (generated by scripts/build-realm-bundle.mjs)
// @cardstack/<lib> — realm bundle (ESM)
// Source: <local-lib-source-dir>
// Regenerate: cd <local-lib-source-dir> && npm run realm
export * from './<lib>/index';
```

Cards then:

```ts
import { someExport } from '../<lib>';
```

**Gotchas:**
- Path is `'../<lib>'` from a card one level deep (e.g. inside `<realm>/foo-folder/`). Use `'./<lib>'` from a top-level card.
- The shim is **generated** — never edit by hand. Re-run `npm run realm` from the upstream project to regenerate.
- Keep the shim a one-line `export *` re-export so the symbol surface stays at the index level.
- Chunks should be split on lazy-loadable feature boundaries so the realm prerenderer streams them when needed.

**Source:** three live examples in the workspace's `common-libs`-style realms — `bxl.ts` + `bxl/` chunked bundle, `surfaces/index.js` + chunked subdirs, `ember-flow-dependencies.js` (single-file variant).
